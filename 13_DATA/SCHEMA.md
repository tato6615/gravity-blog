# 13_DATA / SCHEMA.md

Live schema of the `gravity_affiliate` D1 database, pulled directly from
`sqlite_master` on 2026-09-12. This is the actual system — not the plan.
D1 binding name is `DB` everywhere (Worker `af`'s `wrangler.toml`/dashboard
settings AND this Pages project's `wrangler.toml` both point at the same
database, `da05a906-cf21-4717-a96f-c1da3966fd56`).

**Correction to prior docs:** `12_AI_CONTEXT/ONBOARDING.md` and
`PROJECT-STATUS.md` (last updated 2026-08-10) describe Grist as the source
of truth for products/content/analysis, with D1 holding only
clicks/conversions/email_subscribers. That migrated: as of the
2026-09-05/09-08 `GRAVITY FIX` commits in Worker `af` (see that Worker's
`db.js` and `import.js` header comments), **D1 is the source of truth for
everything** — `functions/_lib/d1-products.js` / `d1-articles.js` in this
repo already read products/content straight from D1. Those two docs should
be treated as historical/stale on this point until someone updates them.

## Business tables (pre-existing — Step 1 does not modify any of these)

| Table | Key columns | Notes |
|---|---|---|
| `products` | id, product_name, brand, category, affiliate_link, price, image_url, rating, pipeline_status, pipeline_step, pipeline_error, source_url, category_th, published_at, channels, shotstack_render_id, video_url/status | Core product record + pipeline state. `market_id` is referenced by Worker af's `import.js`/`pipeline.js` but not present in this dump — confirm before relying on it. |
| `ai_analysis` | product_id (FK), product_summary, brand, category, specifications, features, pros, cons, target_audience, estimated_commission, language | AI-generated product analysis, one row per product+language. |
| `keywords` | product (FK), primary_keyword, supporting_keywords, search_intent, long_tail, comparison/problem/best/review/price/alternative/faq keywords | SEO keyword research per product. |
| `content` | product_id (FK), slug, seo_title, meta_description, blog_draft, review, buying_guide, comparison, alternatives, quality_score, quality_tier, quality_warnings, language | Generated article content. `quality_tier` is informational only — no publish gate reads it (removed 2026-09-09c). |
| `social` | product_id (FK), facebook_post, threads_post, x_post, pinterest_post, telegram_post, discord_post, mastodon_post, tumblr_post, youtube_script, shorts_script, affiliate_cta, language | Per-platform social copy. |
| `ai_media` | product (FK), image_prompt, thumbnail_prompt | AI image/thumbnail prompts. |
| `ai_analytics` | product (FK), views, clicks, conversions, last_updated | Rolling counters, updated atomically via `incrementAnalyticsCounter()` in Worker af's `db.js`. |
| `clicks` | product_id, timestamp, referrer, utm_source, utm_medium, user_agent, ip, event_type | Raw click log (bot-filtered at write time in `analytics.js`). |
| `conversions` | product_id, commission, order_id (UNIQUE), status, timestamp | **The only real-revenue table.** `order_id` UNIQUE makes conversion webhooks idempotent. This is what Revenue Agent reads. |
| `markets` | id, name, parent_market_id, level (`market`/`sub_market`), country, category, score_demand/product_depth/money/commission/repeat/problem_intensity/competition/content_potential/gravity_fit/total, content_angles, ai_reasoning, status (`candidate`/`selected`/`archived`), search_run_id | Market Discovery Engine output — added 2026-09-08, generated by Worker af's `market-discovery.js` (no git; Cloudflare Dashboard Quick Edit only). Functionally overlaps with the ARS spec's Market Agent + Opportunity Agent. |
| `publish_log` | product_id (FK), channel, status, live_url, published_at, post_id, note | Append-only log, one row per publish attempt per channel. |
| `publish_queue` | product_id, channel, status, processed_at | Scheduling queue for distribution. |
| `email_subscribers` | email (UNIQUE), name, subscribed_at | Newsletter list. |
| `settings` | key (PK), value, updated_at | Generic key/value app config (e.g. `community_platforms`). |
| `system_health_log` | checked_at, overall, ok_count, warn_count, error_count | History for `/api/system-health`. |
| `product_first_seen` | product_id (PK), first_seen_at | First-seen timestamp, used by the homepage "new" badge. |
| `articles_fallback_cache` | lang (PK), data, updated_at | Cached article list per language. |

## Agent tables (GRAVITY ARS STEP 1 — new, additive only)

| Table | Purpose |
|---|---|
| `agents` | Identity + live status for the 13 agents. See `02_SYSTEMS/AGENT_ORCHESTRATION.md`. |
| `agent_tasks` | Shared task/message bus between agents. |
| `agent_memory` | Namespaced, persistent key/value shared memory. |
| `agent_logs` | Append-only per-agent activity/error log. |

Full column definitions for these four are in
`functions/_lib/agents/db.js` (the CREATE TABLE statements were run
directly against D1, not through a migration file, since this dump is
already the live source of truth).

## How to keep this file honest

Whenever a column is added/removed/renamed, run this against the D1
console/API and diff it against the table above before merging:

```sql
SELECT name, sql FROM sqlite_master WHERE type='table' ORDER BY name;
```
